## Experiment 7: Destination Receiver Unavailable and Bounded Retry Test

**Configuration:** One DATA packet, 1-second ACK timeout, and maximum 2 retransmissions. The destination host was not listening.

**Results:**
- Total packets attempted: 1
- Successfully acknowledged: 0
- Failed packets: 1
- Retransmissions: 2
- Total transmission attempts: 3
- Final result: Failed after 3 attempts

**Observation:** The sender did not receive an ACK. It waited for the configured timeout, retransmitted the packet twice, and stopped after the third attempt. This confirms bounded retry behavior when the destination is unavailable.

## Overall Experiment Comparison

| Test condition | Best-effort | Reliable UDP |
|---|---:|---:|
| 0% packet loss | 60/60 (100%) | 60/60 (100%) |
| 5% packet loss | 38/60 (63.33%) | 60/60 (100%) |
| Retransmissions at 5% | 0 | 14 |

**Overall observation:** Under 0% packet loss, both methods achieved 100% success. Under 5% configured packet loss, best-effort communication delivered 38 of 60 probes, while reliable UDP acknowledged all 60 DATA packets using 14 retransmissions. These results demonstrate the benefit of acknowledgments and retransmissions for improving delivery reliability.

**Experiment limitations:** The best-effort tests used PROBE/ECHO packets, while reliable tests used DATA/ACK packets. The tests were not fully identical in packet type or sending behavior. Elapsed time, throughput, and a controlled sending rate were not measured. Deliberately dropping one DATA packet and one ACK packet was not tested separately. The results should therefore be interpreted as an observed comparison rather than a fully controlled performance evaluation.

## Updated Overall Experiment Comparison

The following table summarizes the three repeated runs for each test condition.

| Test condition | Best-effort UDP | Reliable UDP |
|---|---:|---:|
| 0% loss, 0 ms delay | 60/60 (100%) | 60/60 (100%) |
| 5% loss, 0 ms delay | 38/60 (63.33%) | 60/60 (100%) |
| 0% loss, 50 ms delay | 60/60 (100%) | 60/60 (100%) |
| 5% loss, 50 ms delay | 60/60 (100%) | 60/60 (100%) |

For the 5% loss and 50 ms delay condition, the reliable UDP runs required 6 total retransmissions across 60 DATA packets. The three repeated best-effort runs had no observed failures. An earlier separate best-effort run under the same configuration recorded 14 successful responses out of 20.

## Updated Experiment Limitations

The best-effort tests used PROBE/ECHO packets, while reliable UDP tests used DATA/ACK packets. Therefore, the comparison is not a perfectly controlled comparison of identical packet types or sending behavior.

Packet loss was randomly simulated. A configured 5% loss rate does not mean exactly 5% of packets will be dropped in every small test. No random seed was recorded.

One reliable UDP performance measurement was completed under 5% packet loss and 50 ms delay. It took 7.788 seconds for 20 packets, approximately 2.57 packets per second. This is a single application-level measurement, not an average across repeated trials or a pure network-latency measurement.

Deliberately dropping a selected DATA packet and a selected ACK packet was not tested separately. The results should be understood as observations from the implemented test conditions rather than a complete controlled network-performance evaluation.
